# タイマーとStateless UX

WireGuardでは、**自分の秘密鍵と相手の公開鍵**を設定するだけでパケットを送れます。セッションの維持、完全前方秘匿性、ハンドシェイクなどはすべて**バックグラウンドで処理**されます。白書では、**利用者からはステートレスに見える**と表現されています。

同様の設計を持つ以前のVPNには多くのバグがありましたが、WireGuardは非常に単純な**タイマー状態機械**で解決しています。

## 1. 基本となる事項

**タイマー状態機械**は、次の定数に基づいて動作します。

| Symbol                  | Value                     |
| ----------------------- | ------------------------- |
| `Rekey-After-Messages`  | 2^60メッセージ            |
| `Reject-After-Messages` | 2^64 - 2^13 - 1メッセージ |
| `Rekey-After-Time`      | 120秒                     |
| `Reject-After-Time`     | 180秒                     |
| `Rekey-Attempt-Time`    | 90秒                      |
| `Rekey-Timeout`         | 5秒                       |
| `Keepalive-Timeout`     | 10秒                      |

> **Rekey**とは、暗号鍵を定期的に更新することです。

WireGuardは、いかなる場合も`Rekey-Timeout`の期間内に接続要求を重複して送信しません。

ハンドシェイク応答の受信に成功すると、セキュアなセッションが作られます。タイマー満了による接続要求には一定の**ジッター（ランダムな遅延）**が加わり、両ピアが同時にハンドシェイクを繰り返す衝突を防ぎます。

## 2. 送信メッセージの制限

セキュアなセッションは、次のどちらかの条件で定期的に**鍵更新**されます。

1. **メッセージ数の制限**：`Rekey-After-Messages`以上のデータメッセージを送信したら**鍵更新**します。
2. **時間の制限**：`Rekey-After-Time`が経過したら**鍵更新**します。

**同時集中の問題（Thundering Herd Problem）**を防ぐため、**現在のセッションの開始側**だけが鍵更新を主導します。

> **Thundering Herd Problem**：双方が同時に鍵交換を要求する問題です。

鍵更新に失敗して`Reject-After-Time`が経過すると、新しい1-RTTハンドシェイクが成功するまで**通信を遮断**します。

## 3. 鍵のローテーション

WireGuardは**完全前方秘匿性（Perfect Forward Secrecy）**を保証します。鍵が漏えいしても過去の通信を復号できないよう、鍵を継続的に更新します。

ただし、ネットワークの遅延で古い鍵を使ったパケットが遅れて届く場合、その鍵がなければ破棄する必要があります。

これを防ぐため、WireGuardは`Current`、`Previous`、`Next`の三つの鍵をメモリに保持します。ハンドシェイクが完了すると、`Next`が`Current`に、`Current`が`Previous`になり、古い`Previous`は消去されます。

## 4. ハンドシェイクの開始と再送

有効なセッションがない状態でデータを送るとき、**最初のハンドシェイク**は次のように進みます。

1. 送信予定のデータパケットをキューに一時保存します。
2. ハンドシェイクメッセージを送信します。
3. 応答が届いたらセッションを確立し、キューのデータを送信します。

要求を送っても`Rekey-Timeout`の間に応答がなければ、次のように**再送**します。

1. **新しいランダムな鍵**を生成し、再びハンドシェイクを試みます。
2. `Rekey-Attempt-Time`の間、5秒ごとに繰り返します。

## 5. Passive Keepalive

> **沈黙は美徳です。**

WireGuardは送るデータがなければ何も送りません。そのため、相手が接続の生存を判断できるよう、次の方法を使います。

- 相手がこちらへデータを送ります。
- こちらには送り返すデータがありません。
- **「接続は生きています」**と知らせるため、空のパケットを送ります。

これにより相手は、接続が切れたために応答がないのか、単に静かなだけなのかを判断できます。
