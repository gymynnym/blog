# パケットの送受信フロー

説明には、以下の暗号鍵ルーティングテーブルを使います。

| Interface Public Key | Interface Private Key | Listen |
| -------------------- | --------------------- | ------ |
| `HIgo...8ykw`        | `yAnz...fBmk`         | 41414  |

| Peer Public Key | AllowedIPs                       |
| --------------- | -------------------------------- |
| `xTIB...p8Dg`   | 10.192.122.3/32, 10.192.124.0/24 |
| `TrMv...WXX0`   | 10.192.122.4/32, 192.168.0.0/16  |
| `gN65...z6EA`   | 10.10.10.230/32                  |

このテーブルを使うWireGuard仮想インターフェース`wg0`の送受信フローは、次のとおりです。

## wg0からパケットを送信するとき

IPパケットの送出インターフェースとして`wg0`が選ばれた場合：

1. 平文パケットがWireGuardインターフェース`wg0`に**到着**します。
2. 宛先IPアドレスから**ピアを選択**します（AllowedIPsテーブルを参照）。
   - 例：宛先IPアドレス192.168.87.21を確認し、AllowedIPsテーブルからピア`TrMv...WXX0`を選びます。
   - 一致するピアがなければ破棄します。カーネルではICMPの「no route to host」、ユーザー空間では`-ENOKEY`エラーにつながる場合があります。
3. 選択したピアのセッション鍵で**暗号化**します。
   - 例：ピア`TrMv...WXX0`の送信用共通鍵とnonceカウンターを使い、**ChaCha20-Poly1305**で平文パケットを**暗号化**します。
   - **送信用共通鍵（symmetric sending encryption key）**：ハンドシェイクで導出されたセッション共通鍵のうち、送信方向に使う鍵です。
   - **nonceカウンター**：データパケットごとに1ずつ増えるメッセージ番号です。**nonceとして使い、鍵とnonceの組み合わせの再利用を防ぎ**、リプレイされたパケットを除外します。
4. 暗号化したパケットの前にWireGuardの**メッセージヘッダー**を付けます。
5. UDPパケットにカプセル化し、相手ピアへ**送信**します。
   - ヘッダー＋暗号文。
   - 宛先はピアのエンドポイント（外部IP:port）です。
   - エンドポイントは設定済みの値、または最近**正常に認証された受信パケットの外側の送信元IP:port**に更新された値です。
   - エンドポイントが不明なら破棄します。

## wg0がパケットを受信するとき

外部からUDPポート41414（待ち受けポート）にパケットが届いた場合：

1. 設定されたUDPポート（例：41414）でWireGuardパケットを**受信**します。
2. ヘッダーからセッションとピアを特定し、**カウンターの検証と認証・復号を試みます**。
   - ヘッダー情報から、どのピアのどのセッションか調べます。
   - メッセージカウンターを検証し、リプレイ攻撃を防ぎます。
   - そのセッションの受信用鍵で**認証（Poly1305）と復号を試みます**。
   - ピアが見つからない場合や認証に失敗した場合は破棄します。
3. 認証に成功したら、外側の送信元IP:portで**エンドポイントを更新**します。
4. 復号した内側の平文パケットがIPパケットか確認し、AllowedIPsで**送信元を検証**します。
   - 復号結果がIPパケットでなければ破棄します。
   - IPパケットなら、その送信元IPをAllowedIPsテーブルで検索し、本来どのピアにルーティングされるべきか確認します。結果が送信したピアと一致すれば通し、一致しなければ破棄します。
5. 検証済みのパケットを`wg0`の受信キューに追加します。

## なぜAllowedIPsを送信ルーティングと受信検証の両方に使うのか？

- **送信時**：宛先IP -> 送信先のピアを決定します。
- **受信時**：送信元IP -> そのIPが本来どのピアから来るべきか検証します。

この方法は、結果としてIPとピアの1対1の対応を強制します。あるIPから届いたパケットに返信するときは、必ず同じピアへ送られます。白書では、逆方向パスフィルタリングに似た効果と説明されています。
