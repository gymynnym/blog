# 暗号鍵ルーティング

> WireGuardでは、ピアを32バイトの`Curve25519`公開鍵で識別します。

WireGuardの**暗号鍵ルーティング**とは、「ピアの公開鍵」と「許可された送信元IPアドレス」を組み合わせ、パケットをどのピアへルーティングするか決める仕組みです。

## 暗号鍵ルーティングテーブル

以下はWireGuardの**暗号鍵ルーティングテーブル**の例です。

| Interface Public Key | Interface Private Key | Listen |
| -------------------- | --------------------- | ------ |
| `HIgo...8ykw`        | `yAnz...fBmk`         | 41414  |

| Peer Public Key | Allowed Source IPs               |
| --------------- | -------------------------------- |
| `xTIB...p8Dg`   | 10.192.122.3/32, 10.192.124.0/24 |
| `TrMv...WXX0`   | 10.192.122.4/32, 192.168.0.0/16  |
| `gN65...z6EA`   | 10.10.10.230/32                  |

インターフェースには**一つの秘密鍵と待ち受けるUDPポート**があり、その後にピアの一覧が続きます。各ピアは公開鍵で識別され、許可された送信元IPアドレスの一覧を持ちます。

WireGuardインターフェースから送信するパケットがあると、このテーブルを参照して暗号化に使う公開鍵を決めます。受信時には復号と認証の後、送信元IPアドレスがそのピアのAllowed Source IPsに含まれるか確認します。検証に失敗したパケットは破棄されます。

WireGuardがこのような単純な原理で動作できるのは、IPsecとは異なり、第3層に厳密に基づくことで、より明快なネットワーク設計を求めるためです。

## Endpoint

**暗号鍵ルーティングテーブル**でピアの外部IP:port（エンドポイント）を指定することは任意です。ピアから認証済みのパケットを受け取ると、そのパケットの外側の送信元IP:portを使ってエンドポイントを自動更新します。

> ピアの外部IP:portを明示すると、最初の接続を開始するアドレスは固定されますが、それ以降は実際に観測されたアドレスにエンドポイントが更新されます。

## ローミング（移動性）

ピアはIPアドレスではなく公開鍵で識別されるため、ネットワーク上の位置が変わっても、新たに受信した認証済みパケットの送信元IP/portでエンドポイントが自動更新されます。

## Listening Port == Source Port

WireGuardは、ピアの待ち受けポートと、そのピアが送信するパケットの送信元ポートを同じに保ちます。構造が単純になり、NAT環境での信頼性も高まるため、NATセッションを長時間維持する必要がありません。例外的な場合はkeepalive設定で維持できます。
